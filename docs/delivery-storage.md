# 登録拠点への帰還とチェスト収納

Issue #13 は #12 の建築保護を前提にする。帰還先・収納先は利用者の明示登録だけから取得し、未登録のチェストを自動探索して使わない。従来の依頼者へ戻る操作は保持する。

## 登録

`register_delivery_target` の `home` はBot現在位置を拠点として記録する。`chest` は利用者が明示した座標を指定し、5ブロック以内で現在のチェストをサーバー側でも確認する。座標が不明な指示では確認を求める。`get_delivery_targets` は登録を読み、`forget_delivery_target` は指定登録を削除する。同じ種別を再登録すると訂正になる。操作は認可済み利用者の明示メッセージに限り、状態再評価からは変更しない。

記憶schema v3は利用者別の専用テーブルにworld識別子・dimension・位置を保存する。収納先はサーバー側のチェスト個体とblock状態も記録する。再起動後に復元し、通常の場所記憶から収納先を推測して補完しない。

Paper補助は、明示登録時に指定チェストのpersistent metadataへ識別子を付ける。持ち物は変更しない。単一・二連チェストを扱い、二連は両方の個体を照合する。置き直し、二連構成変更、施錠で一致しなくなった場合は再登録を要する。管理者がNBTを丸ごと複製する等の直接編集は識別根拠を迂回し得るため、登録を削除して再確認する。worldを別serverへコピーした場合も登録を使い回さない。

## 実装・検証の境界

現在のcommitは登録・訂正・削除・保存・再起動復元の責務を扱う。帰還・収納の実行とゲーム内照合は後続commitで追加する。稼働サーバーへの適用と実world変更は別の許可後に実施する。
