# 登録拠点への帰還とチェスト収納

Issue #13 は #12 の建築保護を前提にする。帰還先・収納先は利用者の明示登録だけから取得し、未登録のチェストを自動探索して使わない。従来の依頼者へ戻る操作は保持する。

## 登録

`register_delivery_target` の `home` はBot現在位置を拠点として記録する。`chest` は利用者が明示した座標を指定し、5ブロック以内で現在のチェストをサーバー側でも確認する。座標が不明な指示では確認を求める。`get_delivery_targets` は登録を読み、`forget_delivery_target` は指定登録を削除する。同じ種別を再登録すると訂正になる。操作は認可済み利用者の明示メッセージに限り、状態再評価からは変更しない。

記憶schema v3は利用者別の専用テーブルにworld識別子・dimension・位置を保存する。収納先はサーバー側のチェスト個体とblock状態も記録する。再起動後に復元し、通常の場所記憶から収納先を推測して補完しない。

Paper補助は、明示登録時に指定チェストのpersistent metadataへ識別子を付ける。持ち物は変更しない。単一・二連チェストを扱い、二連は両方の個体を照合する。置き直し、二連構成変更、施錠で一致しなくなった場合は再登録を要する。管理者がNBTを丸ごと複製する等の直接編集は識別根拠を迂回し得るため、登録を削除して再確認する。worldを別serverへコピーした場合も登録を使い回さない。

## 帰還・収納

`gather_and_store` は指定種類・指定数の原木を安全に収集し、登録拠点への到達を観測した後、指定チェストへ収納する。`store_logs` は現在所持する指定数を帰還・収納する。どちらも両方の登録が必須で、別world、個体不一致、経路不明、距離上限超過では停止する。

採取前に現在地→拠点→チェストの距離上限を確認する。採取と探索は拠点から帰還できる範囲へ制限し、ドロップ回収の移動分も内側に確保する。チェストが遠方・未読込で照会できない場合は消失と断定せず、登録した拠点経由で接近して個体を確認する。収集付きの依頼ではその確認後に採取を始め、所持品だけの収納では帰還・接近後に確認する。収納直前の個体再確認は省略しない。遠方への帰還は32ブロック以下の区間に分け、各区間でworldと進行を確認する。障害物を越える経路を推測して強制移動せず、区間の経路を得られない場合は停止する。

作業全体で一つの操作ロックを保持し、探索・採取・移動・収納を中断できる。収納中は対象原木をBotのinventoryから指定チェストへ動かすclickだけを使う。サーバー補助でもチェストからの取得・交換・投棄を拒否する。収納のために空けたBot側のslotを落ちている物の回収で埋めないよう、コンテナ操作中のitem pickupを止める。無関係な所持品を整理したり持ち出したりしない。

Mineflayerのslot予測だけでは完了としない。サーバーから得た操作前後のBot所持数とチェスト内容数を照合する。他プレイヤーのclick・drag、ホッパー等の物品移動を検出した場合や、観測世代が変わった場合は収納数を未確認とする。管理コマンドや他pluginからの直接inventory編集は監視イベントを迂回し得るため、作業中は行わない。

満杯・一部収納・停止は全量完了と報告しない。確認できた収納数、依頼数の残り、対象原木の現在所持数を分けて返す。観測できない値は未確認にする。停止・危険介入・切断・失敗でコンテナを閉じ、移動を止め、操作ロックを解放する。コンテナを開く処理自体が応答しない場合は、遅延した操作を残さないためBotの接続を終了する。

再実行は新しい依頼として現在所持数と新しい観測差分から判断し、以前の収納数を加算しない。途中収納の残りを依頼するときは、現在の所持数を確認して `store_logs` を使う。

## 検証・適用

自動テストで登録権限、保存・復元、未登録、成功、満杯、対象変化、停止、一部収納、再実行、既存物資の保持、同時変更の未確認判定を確認する。実ゲームでは専用の新規test worldで自然成長した木と建築用原木を用意し、収集・帰還・収納・停止と実所持数を照合する。自動テストだけで実ゲーム項目を完了にしない。

稼働サーバーへの適用と実world変更は別の許可後に実施する。
